# Runtime Verification — API 36 Emulator

**Status: verified on the Android SDK emulator (API 36, x86_64, SwiftShader).
Not verified on Cuttlefish or physical hardware.**

This records what was actually executed and measured. It supersedes the
"no measurements exist" claim in `m7`, which still holds for AOSP/Cuttlefish
and for the device.

## Build

`scripts/build-emulator-apks.sh` drives `aapt2`, `kotlinc`, `d8` and
`apksigner` directly against `android-sdk/` — no Gradle, no Soong.
`scripts/fetch-androidx-deps.py` resolves the AndroidX closure from Maven POMs
into `thirdparty/`.

All four modules build:

```
OK  appleux-design-system.apk   (2.8M)
OK  appleux-performance.apk     (2.8M)
OK  appleux-launcher.apk        (2.8M)
OK  appleux-settings.apk       (2.8M)
```

`appleux-design-system.apk` and `appleux-performance.apk` are library artifacts
with no `<application>` element. `adb install` rejects them; that is expected.

## Cross-process settings — verified

The launcher and settings app are separate processes. `Settings.System` cannot
be the shared store on Android 16 (any app write raises
`IllegalArgumentException: You cannot keep your settings in the secure
settings`, which crashed the Settings UI). The shared store is
`AppleuxConfigProvider`, guarded by a signature-level permission; both APKs are
signed with `tools/debug.keystore`.

Driven from the Settings UI, observing the launcher process:

| Setting | Launcher `proc_pressure_cpu` polls / 8 s | Expected |
|---|---|---|
| adaptive ON (default), low power OFF | 16 | > 0 |
| adaptive OFF | 0 | 0 |
| adaptive ON, low power OFF | 16 | > 0 |
| adaptive ON, low power ON | 0 | 0 |
| adaptive ON, low power OFF | 15 | > 0 |

Dark mode, same path, sampled from a launcher screenshot:
`dark ON -> (0,0,0)`, `dark OFF -> (245,245,247)`.

## Touch — verified

| Interaction | Result |
|---|---|
| Icon taps (Settings, Calendar, Chrome, Clock, Contacts) | launched the matching activity |
| Icon tap, Camera | no-op |
| Swipe up | app library opens (home vs library 12.3% of pixels differ) |
| Swipe down | returns to the exact home screen (0.0% differ) |

Camera does not resolve on this emulator image independently of AppleUX:
`cmd package resolve-activity -a android.intent.action.MAIN
-c android.intent.category.LAUNCHER -p com.google.android.apps.camera` returns
"No activity found".

## Defects found and fixed during this verification

1. Settings UI crashed on every switch toggle (Android 16 `Settings.System`
   write rejection). Replaced with a ContentProvider; failed writes now revert
   the switch instead of throwing.
2. `AppleuxRuntimeConfig.readBoolean` queried the whole provider table and took
   the first row, aliasing all four flags to whichever was written first.
   Reads now use per-key URIs.
3. `GestureHandler` used a clickable transparent overlay covering the launcher
   root, which consumed every tap and made app icons unlaunchable. Replaced with
   observation in `GestureHostLayout.dispatchTouchEvent`.
4. `GestureDetector.onFling` never fired for full-height emulator swipes, so
   the library could not be opened. Swipes are now measured from DOWN/UP.
   Swipe-down additionally required handling `ACTION_CANCEL`, because a
   scrolling child converts the rest of the gesture.
5. `AppleuxHaptics` threw `SecurityException: vibrate` on every swipe because
   the launcher manifest did not declare `VIBRATE`; each swipe killed the app.
   The permission is declared and all vibration is best-effort. The earlier
   "swipe-up works" reading was a false positive caused by this crash.
6. Homescreen icons rendered at 60 px instead of ~157 px:
   `IconTokens.SYSTEM_ICON_SIZE_HOME_SCREEN` is expressed in dp but was assigned
   as pixels, and the icon and label overlapped in a `FrameLayout`. The cell
   layout now stacks them, and the size is converted with display density.
7. The first icon row rendered under the status bar (target SDK 35+ is
   edge-to-edge). The launcher root now applies system-bar insets.
